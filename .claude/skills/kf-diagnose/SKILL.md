# kf-diagnose — 标准化调试循环

> **核心**：没有反馈循环不修复。无 loop 不假设。
>
> 基于 Matt Pocock `/diagnose` 方法论，提供系统化 bugfix 流程。

---

## 触发方式

| 方式 | 示例 |
|------|------|
| 直接描述 bug | "订单列表页面白屏" |
| `/kf-diagnose` | `/kf-diagnose 用户登录后跳转失败` |
| 显式调用 | "用 diagnose 流程排查这个 500 错误" |

---

## 调试循环

```
Phase 1: 构建反馈循环（30% 工作量）
Phase 2: 复现 bug
Phase 3: 生成 3-5 个假设（同时生成，防止锚定）
Phase 4: 逐一验证（一次一变量）
Phase 5: 修复 + 回归测试
Phase 6: 清理 + 复盘
```

---

## Phase 1 — 构建反馈循环

**这是最重要的一步，占 30% 工作量。没有反馈循环不修复。**

根据项目类型选择反馈机制：

| 类型 | 反馈机制 | 验证方式 |
|------|---------|---------|
| 后端 API | `curl` 命令 + 预期 JSON 响应 | 状态码 + 响应体对比 |
| 前端页面 | 浏览器打开 + 截图对比 | 页面渲染 + 控制台日志 |
| 单元测试 | `npm test -- --grep <test-name>` | 测试输出 |
| 数据库 | 直接 SQL 查询 | 数据状态验证 |

**产出**：一个可重复使用的反馈命令/脚本，能在 1 秒内给出通过/失败信号。

### Gate 1 — 反馈循环就绪，MUST 可复现 bug 的症状。

---

## Phase 2 — 复现 bug

使用 Phase 1 的反馈循环，复现 bug。

- 记录复现步骤（精确到输入参数）
- 记录观测到的错误现象（截图 / 日志 / 堆栈）
- 判断是否稳定复现

### Gate 2 — bug 稳定复现，可观察到可度量的失败信号。

---

## Phase 3 — 生成 3-5 个假设

**同时生成**，不逐个追问，防止认知锚定。

每个假设包含：

| 维度 | 内容 |
|------|------|
| 根因推测 | 基于代码阅读的推断 |
| 证据 | 代码中支持该推测的证据 |
| 预期结果 | 如果假设成立，反馈循环的输出应该是什么 |
| 验证方案 | 如何用最小的改动验证（一次一变量） |

### 假设方向

| 方向 | 典型问题 |
|------|---------|
| **数据层** | 状态不一致、字段缺失、类型不匹配、数据库约束 |
| **逻辑层** | 条件分支错误、状态转换遗漏、边界未处理、竞态条件 |
| **UI 层** | 响应体结构假设错误、字段名不同、缺少兜底渲染 |
| **配置层** | 环境变量、URL 路径、跨域、代理 |
| **第三方** | Mock 与真实服务签名不一致、超时、重试逻辑 |

### Gate 3 — 至少 3 个假设，每个含证据和验证方案。

---

## Phase 4 — 逐一验证（一次一变量）

对一个假设进行验证时，**只改动一个变量**。

```
验证循环：
1. 修改代码（最小改动）
2. 运行反馈循环
3. 观测结果（通过/失败）
4. 恢复修改（如果失败）
5. 进入下一个假设
```

**铁律**：一次只改一个东西。同时改两处 = 不知道哪个修好的。

### Gate 4 — 找到根因，假设验证通过。

---

## Phase 5 — 修复 + 回归测试

1. 实施修复（最小改动）
2. 运行反馈循环确认 bug 消失
3. 运行完整测试套件（`npm test`）
4. 如果有 Gate 门禁 → 运行 `regression-runner.mjs` 从当前阶段验证
5. 记录修复摘要

### Gate 5 — 修复通过回归测试。

---

## Phase 6 — 清理 + 复盘

1. 删除调试用的临时代码（console.log、临时 URL、硬编码值）
2. 检查是否需要更新 `docs/CONTEXT.md`（是否暴露了术语歧义）
3. 检查是否需要创建 ADR（如果修复涉及架构决策）
4. 输出复盘摘要

**复盘模板**：
```
## 复盘: <bug 标题>
- 现象: <观测到的失败>
- 根因: <代码层面的根因>
- 修复: <做了什么>
- 假设数: <共生成了几个假设，第几个命中>
- 验证轮次: <共跑了几个验证循环>
- 可预防: <如何防止同类问题>
```

### Gate 6 — 清理完成，复盘记录可追查。

---

## 验证命令

| 阶段 | 命令 |
|------|------|
| Gate 1 | `curl <endpoint>` 或 `npm test -- --grep <test-name>` |
| Gate 2 | 同 Gate 1，确认失败输出 |
| Gate 3 | 检查假设清单完整性（>=3） |
| Gate 4 | 反馈循环输出通过信号 |
| Gate 5 | `npm test` + `regression-runner.mjs` |
| Gate 6 | 复盘文件存在 |

---

## 集成到 ccmvp

- Bugfix 任务 MUST 使用 `/kf-diagnose` 流程
- 修复完成后 MUST 触发回归验证链（`regression-runner.mjs`）
- 复盘记录写入 `memory/diagnose-log.md`

---

## Iron Rules

1. **没有反馈循环不修复** — Phase 1 未完成不得进入 Phase 2
2. **一次一变量** — 同时改多处 = 不知道哪处修好了
3. **假设同时生成** — 最少 3 个，防止锚定第一个想法
4. **最小改动修复** — 只改与根因相关的代码，不做额外重构
5. **修复 MUST 回归验证** — 单测 + 门禁链
6. **复盘 MUST 记录** — 写入 `memory/diagnose-log.md`
