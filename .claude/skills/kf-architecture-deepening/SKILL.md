# kf-architecture-deepening — 架构持续深化

> **核心**：识别代码库中的浅模块，持续深化架构，防止技术债务失控。
>
> 基于 Matt Pocock `/improve-codebase-architecture` 方法论。

---

## 执行时机

| 时机 | 说明 |
|------|------|
| **MVP 完成后每 3 天** | 定期审视，防止债务累积 |
| **Bugfix 后** | 评估是否需要架构改进 |
| **新功能引入前** | 检查当前架构是否支持新需求 |
| **显式触发** | `/kf-architecture-deepening` |

## 检查维度

### 维度 1 — 浅模块 → 深模块机会

检查代码中那些"只有一个函数的模块"或"只有一个方法的服务"。浅模块意味着抽象不完整或者过早解耦。

**症状**：
- 一个模块只有一个导出函数
- 一个文件只有 10-20 行且逻辑简单
- 一个类只有一个方法被外部调用

**深化方向**：合并相关模块，或给模块增加正确的抽象边界。

### 维度 2 — 测试盲区

检查哪些逻辑路径没有被测试覆盖。

**症状**：
- 条件分支没有对应的测试用例
- 错误处理/异常路径没有测试
- 边界值没有测试
- 新功能合并后测试覆盖率下降

**深化方向**：补充测试用例，优先覆盖边界和异常路径。

### 维度 3 — 语义耦合

检查不同模块之间的依赖是否符合直觉。如果 A 模块依赖 B 只是因为"运行时需要"，而不是因为"领域逻辑需要"，就是语义耦合。

**症状**：
- 一个模块的修改导致多处不相关的测试失败
- 修改了一个底层函数，上层调用者大量变更
- 跨模块的隐式契约（如某个字段的格式）

**深化方向**：明确模块边界，减少隐式依赖。

### 维度 4 — 命名一致性

检查变量名、函数名、文件名是否与 `docs/CONTEXT.md` 定义的术语一致。

**症状**：
- 同一个概念在不同文件中使用不同名称
- 文件名与内部函数名不匹配
- 使用了 CONTEXT.md 中"避免使用的词"

**深化方向**：统一命名，更新 CONTEXT.md 或修复代码。

## 执行流程

### Step 1 — 全景扫描

读取当前代码库结构，了解模块划分和文件组织。

- 读取 `docs/CONTEXT.md` 了解领域术语
- 读取 `docs/adr/` 了解架构决策历史
- 列出项目所有主要目录和模块

**产出**：模块一览表（模块名 / 文件数 / 行数 / 上次修改）

### Step 2 — 逐个维度审视

对每个维度运行对应的检查脚本或代码分析：

| 维度 | 分析方法 |
|------|---------|
| 浅模块 | `wc -l` 每个文件，标出 <20 行的模块 |
| 测试盲区 | `grep -r "it("` / `describe(` 与源文件对比 |
| 语义耦合 | 分析 import 依赖图（`grep -r "from.*../"`） |
| 命名一致性 | grep CONTEXT.md 术语 vs 代码中实际用词 |

### Step 3 — 汇总发现

按严重程度排列：

| 级别 | 定义 | 行动 |
|------|------|------|
| **P0** | 阻止开发效率的问题 | 立即修复 |
| **P1** | 导致未来 bug 的风险 | 计划修复 |
| **P2** | 可改善但非必要的 | 记录待办 |

### Step 4 — 建议深化方案

对每个发现，给出具体的深化建议：

```
## 发现: <文件名>:<行号>
- 类型: 浅模块 / 测试盲区 / 语义耦合 / 命名一致
- 当前状态: <代码片段或描述>
- 风险: <不修复的后果>
- 建议: <具体修改方案>
- 工作量: <预估时间>
```

### Step 5 — 用户确认 + 执行

询问用户哪些深化方案需要立即执行。执行后验证：

1. 修改后的测试是否通过
2. 修改是否引入了新的浅模块
3. CONTEXT.md 是否需要更新
4. 是否需要创建 ADR 记录架构变动

## Iron Rules

1. **MUST NOT 做纯代码风格修改** — 聚焦架构问题，不是代码格式
2. **MUST NOT 改写已验证的业务逻辑** — 只做结构性改动
3. **每次修改 MUST 通过测试后提交** — 修改 + 测试 = 原子操作
4. **MUST 更新 CONTEXT.md** — 如果修改暴露了术语不一致
5. **MUST 记录重大架构变动到 ADR** — 如果修改涉及决策性选择
